# 1.2.0: 未打开的视频卡片 + 系统视频目录

用户明确要求：鼠标呈手形的视频封面/链接，未打开时也能 Ctrl+C 下载；统一文件夹位于 Windows 系统“视频”栏。

## 实现决策

- 保留纯插件，不更改 Edge 的全局下载位置。浏览器 downloads API 不能指定绝对路径，因此使用 File System Access API：一次点击选择目录，默认 startIn=videos，句柄保存在扩展自己的 IndexedDB。每次保存检查已有授权，不在后台偷偷弹权限框。
- 选定系统视频目录后保存到其 VideoDownloads 子文件夹。若选的本来就是 VideoDownloads，不创建嵌套目录。目录没选或授权失效时，任务页明确提示并提供选择按钮，成功后继续任务。
- 所有输出经同一保存模块：普通直链流式写盘、Blob、B站合并、音频、封面。拒绝目录穿越，重名编号，取消中止临时写入。
- 视频卡片识别有真实 href 或 data-video-url 的条目；支持 BV/av、视频文件链接，以及具有缩略图/视频语义的常见 /watch、/video 详情页。普通导航链接、javascript 按钮不当作视频。
- 需要解析详情页时只在后台打开用户指向的页面，等待其播放器，不自动点击页面按钮；结果、错误、取消返回原页面。完成后清理插件自行创建的详情页，不关闭用户原有标签页。

## 验证

先让原版本在卡片识别、目录写入、取消、重名测试中失败。真实 Edge 测试卡片下载、后台解析生命周期与持久句柄。目录写入使用真实浏览器 OPFS 句柄验证 IndexedDB、写入与重载；系统 Videos 本身仍需要用户一次目录选择授权，不能声称已自动获得。
